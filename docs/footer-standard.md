# Единый подвал и навигация

Актуальное правило для общего редактора. Внедрение 02.11.2026 выполняется для
миссионерского «Паломника» на ядре №1; запись этого документа не означает
обновление других установок или синхронизацию Google Диска.

- На компьютере: бренд/название, краткое описание и вертикальная навигация слева;
  справа два самостоятельных раздела подписки и личной связи. На телефоне одна колонка.
- «Смотрите и подписывайтесь»: YouTube, Instagram, TikTok, Telegram-канал.
  Согласованные фирменные цвета значков сохраняются.
- «Для связи с проектом»: WhatsApp, Viber, личный Telegram, затем заполненные
  телефон и почта. Значки мессенджеров контурные, без цветной панели.
- Telegram-канал хранится в соцсетях, личный Telegram — в footer.telegram.
  Пустая ссылка может иметь некликабельное обозначение; выдуманных адресов,
  демонстрационных телефонов и пустых tel:/mailto: нет.
- При отсутствии логотипа название выводится один раз, без дублирования.
- Документы и реквизиты берутся из существующих настроек и выводятся при заполнении
  и включённой видимости. Нижняя подпись редактируется; {year} заменяется текущим годом.
  Справа — «Наверх». Ссылку на фотоисточники в подвал не добавлять.
- Меню шапки и подвала используют общие названия. Необязательный переключатель
  «Показывать страницы разделов» выводит только реальные видимые страницы верхнего
  уровня. «О проекте» выводится только при существующем вступительном текстовом блоке.
  Ссылки на связь/соцсети учитывают видимость подвала.
- Все настройки сохраняются редактором и переносятся в JSON/ZIP. Витрина сохраняет
  свою палитру и шрифты; серо-жёлтый стиль относится только к панели управления.

## Совместимость страниц

Страницы существующих редакционных сайтов используют `appearance.page_layout=editorial`:
широкое фото слева, название и обтекающий текст справа; общая ширина 1440 px.
Специализированный путеводитель включается явным `page_layout=guide` в редакторе.
Обновление ядра само по себе не превращает три миссионерских раздела в каталог обителей.

## Переход «Паломника»

Миграция 006 задаёт оформление только при совпадении названия установленного сайта
и трёх существующих миссионерских slugs. Сохранённый presentation не перезаписывается;
фотографии, тексты, порядок элементов, контакты и аккаунт не изменяются.
Полная копия SQLite создаётся механизмом миграций до первого изменения схемы.
Дополнительно перед выкладкой необходима свежая внешняя резервная копия установки.

FTP-выкладка main обновляет только код и исключает рабочую базу, настройки и загрузки.
Эта выкладка не является массовым обновлением клиентских сайтов: публикация ZIP/latest.json
на сервер обновлений допускается только отдельным явным тегом версии.
