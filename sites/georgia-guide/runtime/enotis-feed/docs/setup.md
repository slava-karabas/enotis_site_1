# Установка и подключения

Действующая [спецификация 2.2](spec-2.2.md), разделы 13–14 и 20–21. Версия кода — 2.0.0; это другой номер.


1. Распакуйте сборку в отдельную папку. PHP 8.1+, PDO SQLite, GD, ZIP, mbstring и cURL. Корень сайта — `public/`; приложение и `data/` должны находиться вне публичной папки. Для Apache включите rewrite; для Nginx направьте маршруты в `public/index.php`, выдавая только существующие файлы из `public/`.
2. Дайте PHP право записи в `data/` и `public/uploads/`. Включите HTTPS. Откройте `/admin/install`, создайте собственный вход. Сборка не содержит готовых паролей и контента.
3. В `/admin` заполните шапку, содержимое и подвал, сохраните, проверьте компьютер и телефон. Сайт №1 не принимает оплату. №1.2 поддерживает ссылки, QR и реквизиты. В №2 заказы магазина пока оформляются с ручным согласованием оплаты и доставки; подключение эквайринга — отдельный этап.
4. Перед переносом используйте «Резервные копии». Для лент переносится контент через «Перенос сайта»; код устанавливается отдельно. Для №2 полная переносимая сборка магазина доступна в `/admin/shop/transfer`: код и контент, без входов, заказов и ключей. Локальный резервный архив может содержать закрытые данные — храните его отдельно.
5. Почта: «Интеграции → Отправка писем», затем почта владельца в «Уведомления, CRM и API». На сервере настройте запуск `php /absolute/path/bin/integration-worker.php` раз в минуту. Без расписания очередь не отправляется. Нужна реальная проверка доставки у хостера.
6. CRM: укажите HTTPS webhook. При первом сохранении скопируйте ключ подписи и передайте получателю отдельно. Проверяйте HMAC SHA-256 заголовка `X-Enotis-Signature` по исходному телу и устраняйте повторы по `event_id`. При смене ключа обновите получателя. До пяти попыток доставки, затем ручной повтор из журнала. Реальная внешняя CRM не подключена в демонстрации.
7. API заказов №2: отдельно включите чтение/изменение статуса и создайте ключ. Запросы только по HTTPS с `Authorization: Bearer …`. Чтение: `GET /automation/v1/orders?after=0`, до 50 заказов. До устранения расхождения графа переходов и updated_at (21.3) изменение статусов через агента не считать готовым к запуску. Статус обработки: `POST /automation/v1/orders/{id}/status`, JSON `status`: confirmed/completed/cancelled. API не подтверждает оплату и не меняет цены. В лентах №1/№1.2 подготовлены настройки и очередь; источника заказов и работающего API заказов у них нет.
8. ИИ-обработка и аналитика настраиваются в «Интеграциях». В общем редакторе кнопка «ИИ-обработка» появляется после настройки фотосервиса. Ключи и стоимость услуг задаются отдельно. В каталоге №2 также есть «ИИ-обработка»: сравнение до/после, применение при сохранении и возврат к оригиналу.

Не устанавливайте эту сборку поверх рабочего сайта без проверки копии и отдельного решения о переходе. Канал автоматических обновлений между разными продуктами отключён. Развёртывание и запуск расписания на реальном хостинге в эту поставку не входят.

Перед запуском №2 дополнительно проверьте покупки из вложенных страниц, локализацию, SEO и полный перенос магазина: ограничения перечислены в 21.3 спецификации. Проверки внешних сервисов выполняются на реальной установке отдельно.
